## 🌟 核心语法速记（不用比喻，直白说明）

在深入代码前，了解 5 个关键语法：

| 语法 | 直白说明 | 什么时候用 |
|------|---------|----------|
| `async function` | 一个特殊标记，说明"这个函数里面会等待网络请求" | 函数内部有 `await` 时必须加 |
| `await` | 停下来，等某个事情完成，才继续 | 网络请求前面加 `await` |
| `try/catch` | 如果出错自动捕捉，不会导致程序崩溃 | 网络请求可能失败的地方 |
| `this.某变量` | "当前这个页面组件里的某个变量" | 访问 data 中定义的变量 |
| `this.某方法()` | "当前这个页面组件里的某个方法" | 调用 methods 中定义的方法 |

**最重要的一个流程：**
- 调用 `await uploadFile()` → 停下来等待上传完成 → 上传完成，获得 URL → 继续往下执行
- 如果中间网络失败 → 自动进入 `catch` 块 → 弹错误提示 → 不会导致程序崩溃

## 1️⃣ 页面打开 → onLoad()

**触发时机：** 用户打开 record 页面

### 💡 语法讲解：setInterval 拆解讲解

**setInterval 完整语法：**
```javascript
setInterval(要重复执行的函数, 间隔多少毫秒);
```

这是语法**模板**，真实代码时要用实际值替换它们：

---

**第一个参数：要重复执行的函数**

这个参数说：你希望一遍遍重复执行哪个函数

```javascript
// 例子 1：直接写函数名
setInterval(saveDraft, 3000);
// 参数 1 = saveDraft（这个页面的 saveDraft 方法）
// 意思：重复执行 saveDraft

// 例子 2：前面加 this
setInterval(this.saveDraft, 3000);
// 参数 1 = this.saveDraft（这个页面的 saveDraft 方法）
// 意思：重复执行这个页面的 saveDraft，this 表示当前页面
```

如果函数带参数怎么办？

```javascript
// 不对：这样会立即执行，而不是延迟执行
setInterval(saveDraft(), 3000);  // ❌ 错！

// 对：用括弧 () => {} 包一层
setInterval(() => {
  saveDraft('param1', 'param2');  // 延迟执行，带参数
}, 3000);
```

---

**第二个参数：间隔多少毫秒**

这个参数说：每间隔多少毫秒执行一次

```javascript
setInterval(saveDraft, 1000);      // 每 1000 毫秒（1秒）执行一次
setInterval(saveDraft, 3000);      // 每 3000 毫秒（3秒）执行一次
setInterval(saveDraft, 5000);      // 每 5000 毫秒（5秒）执行一次
setInterval(saveDraft, 60000);     // 每 60000 毫秒（1分钟）执行一次
```

单位一定是**毫秒**，不是秒！

```javascript
// 常见换算
1 秒  = 1000 毫秒
3 秒  = 3000 毫秒
5 秒  = 5000 毫秒
10 秒 = 10000 毫秒
1 分钟 = 60000 毫秒
```

---

**完整例子：把参数代入实际值**

```javascript
// 语法模板
setInterval(要重复执行的函数, 间隔多少毫秒);

// 代入实际值
setInterval(this.saveDraft, 3000);
// ↑ 参数1         ↑ 参数2
```

意思就是：
- 参数1 = `this.saveDraft`（重复执行这个方法）
- 参数2 = `3000`（每 3000 毫秒执行一次）

结果：**这个方法会每 3 秒自动执行一次，永远重复下去**

---

**为什么要保存到变量里？**

```javascript
// 只写参数，不保存
setInterval(this.saveDraft, 3000);
// 问题：定时器启动了，但你没办法停止它！

// 保存到变量
this.draftTimer = setInterval(this.saveDraft, 3000);
// this.draftTimer = 定时器的 ID
// 现在你可以用这个 ID 来停止定时器
```

**停止定时器：**

```javascript
// 启动定时器，保存 ID
this.draftTimer = setInterval(this.saveDraft, 3000);

// ... 

// 停止定时器（使用之前保存的 ID）
clearInterval(this.draftTimer);
```

---

**实际时间轴看看会发生什么：**

```javascript

this.draftTimer = setInterval(this.saveDraft, 3000);

//   第 0-3 秒：等待中...

//   第 3-6 秒：等待中...
//   第 6 秒：saveDraft() 执行 ✓（第 2 次）
//   第 6-9 秒：等待中...
//   第 9 秒：saveDraft() 执行 ✓（第 3 次）
//   第 9-12 秒：等待中...
//   第 12 秒：saveDraft() 执行 ✓（第 4 次）

```

### 💡 超详细讲解：回调函数 onStop((res) => {...})

**首先，最重要的问题：recorderManager 从哪里来？**

在 onLoad() 中有这行代码：
```javascript
this.recorderManager = uni.getRecorderManager();
```

拆解：
- `uni.getRecorderManager()` = 向 UniApp 要一个"麦克风管理器"对象
- `this.recorderManager = ...` = 把这个对象保存到当前页面的 recorderManager 变量

所以 `recorderManager` 就是：
1. 从 UniApp 系统来的
2. 一个麦克风控制对象
3. 保存到了当前页面
4. 之后就可以通过 `this.recorderManager` 来使用它

类比：
```javascript
// 相当于：
// 向苹果公司要一个 iPhone 手机
this.phone = Apple.getPhone();

// 现在你可以用这个手机了
this.phone.call();     // 打电话
this.phone.takePhoto(); // 拍照
```

那 `recorderManager` 有哪些方法能用？因为是 UniApp 提供的，文档里规定了：
- `recorderManager.start(options)` = 开始录音
- `recorderManager.stop()` = 停止录音
- `recorderManager.onStop(function)` = 当停止时执行这个函数
- 等等...

所以你可以这样用：
```javascript
// 第 1 步：想要一个麦克风
this.recorderManager = uni.getRecorderManager();

// 第 4 步：停止录音

// ← 自动触发上面设置的 onStop 函数
```

现在理解了 `recorderManager` 吧？就是麦克风的控制器，从 UniApp 系统来的。

**第二步：理解 onStop() 方法是什么**

`onStop()` 是麦克风管理器提供的一个方法。

意思是：**"当麦克风停止录音时，执行我给你的这个函数"**


问题：你要给它放什么函数？

答案：一个**回调函数**（就是等事件发生再执行的函数）

**第三步：理解 (res) => { ... } 是什么**

这是一个**箭头函数**，长这样：

拆解：
- `(res)` = 参数，麦克风停止时系统给你的信息
- `=>` = 箭头，表示"执行这个函数"
- `{ ... }` = 花括号里是函数的代码

### 💡 额外讲解：this（对于初学者很容易搞混）

看到 `this.` 开头的变量或方法，记住一个原则：

**this = 当前这个页面组件**

```javascript
// 例子 1：访问 data 变量
this.sessionId = 123;
// 意思：把 123 保存到当前页面的 sessionId 变量

// 例子 2：调用 methods 方法
this.loadRecord();
// 意思：执行当前页面的 loadRecord() 方法

// 例子 3：定时器
this.draftTimer = setInterval(this.saveDraft, 3000);
// 意思：把定时器的 ID 保存到当前页面的 draftTimer
//      定时重复执行当前页面的 saveDraft 方法

// 例子 4：获取麦克风
this.recorderManager = uni.getRecorderManager();
// 意思：把麦克风对象保存到当前页面的 recorderManager
```

**为什么要用 this？**
- 因为这是 Vue 页面组件的规则
- data 里定义的变量、methods 里定义的方法，都要用 `this.` 来访问
- 不用 this 的话，代码找不到这些变量和方法
- 看起来复杂，其实就是"当前页面的某个东西"这么简单

### 💡 语法讲解：if/else 拆解

**语法模板：**
```javascript
if (条件) {
  // 条件为 true 时执行这段代码
} else {
  // 条件为 false 时执行这段代码
}
```

**实际例子来看：**
```javascript
toggleRecording() {
  if (this.isRecording) {
    // this.isRecording 为 true 时（正在录音）
    // 停止录音
    this.recorderManager.stop();
  } else {
    // this.isRecording 为 false 时（没有录音）
    // 开始录音
    this.recorderManager.start();
  }
}
```

**代入一个具体的值来看：**

假设 `this.isRecording` 当前是 `false`（没有录音）

```javascript
if (false) {  // ← 条件为 false
  // 这里不会执行
} else {
  // ✓ 这里会执行
  this.recorderManager.start();  // 开始录音
}
```

再点一次，此时 `this.isRecording` 是 `true`（正在录音）

```javascript
if (true) {  // ← 条件为 true
  // ✓ 这里会执行
  this.recorderManager.stop();  // 停止录音
} else {
  // 这里不会执行
}
```

**关键点：**
- 条件为 true → 执行 if 块
- 条件为 false → 执行 else 块
- 一次只执行其中一块，不会两个都执行

---

```javascript
toggleRecording() {
  if (this.isRecording) {
    // ... 停止录音的逻辑（返回值那边）
  } else {
    // ★ 用户第一次点击 → 开始录音

    // 【步骤 1】采集 GPS 位置（知道问题发生在哪里）

      sampleRate: 16000,      // 采样率 16kHz
      numberOfChannels: 1,    // 单声道
    });

```

## 3️⃣ 用户点停止 → onStop() 回调自动触发

**触发时机：** 用户再点一次"录音"按钮

```javascript
toggleRecording() {
  if (this.isRecording) {
    // ★ 用户第二次点击 → 停止录音

    // 【步骤 1】停止麦克风
    this.recorderManager.stop();  // ← UniApp API
    // ↓ 系统立即触发 onStop() 回调 ↓

    // 【步骤 2】改变页面状态
    this.isRecording = false;

    // 【步骤 3】停止计时器
    if (this.timer) {
      clearInterval(this.timer);  // ← 原生 JavaScript API
      this.timer = null;
    }
  }
}
```

**onStop() 回调自动执行：**

### 💡 语法讲解：async、await、try/catch 拆解讲解

**async 是什么？**
```javascript
// 普通函数
function doSomething() {
  console.log('执行');
}

// async 函数（比普通函数多加 async 两个单词）
async function doSomething() {
  console.log('执行');
}
```

`async` 的作用：告诉 JavaScript "这个函数会等待网络请求，里面可以用 await"

为什么要加 `async`？因为函数里有 `await`，必须加

---

**await 是什么？**
```javascript
// 没有 await（错的方式）
const result = uploadFile();      // 开始上传
console.log(result);               // 立即打印
// 问题：result 可能还没有值！文件可能还在上传中

// 有 await（对的方式）
const result = await uploadFile(); // 开始上传 + 等待完成
console.log(result);               // 现在一定有值了
// → uploadFile 完成了，获得返回值
```

`await` 的作用：暂停代码执行，等待网络请求完成，才继续

---

**try/catch 是什么？**
```javascript
// 不用 try/catch（有风险）
const result = await uploadFile();  // 如果网络出错...
console.log(result);                // 程序会直接崩溃！

// 用 try/catch（安全）
try {
  const result = await uploadFile(); // 如果网络出错...
  console.log(result);               // 正常情况
} catch (err) {
  // 程序出错时，自动执行这里
  console.log('上传失败', err.message);
}
// 程序不会崩溃
```

`try/catch` 的作用：
- `try` 块：尝试执行这些代码
- `catch` 块：如果任何一行出错，自动跳到这里处理错误

---

**完整例子拆解：**
```javascript
async handleRecordingDone() {  // ← 有 async，因为下面有 await
  try {
    // 尝试执行这些代码
    const r = await createRecord({id: 123});  // ← 等待完成
    console.log('创建成功');
    
    const result = await uploadFile();        // ← 等待完成
    console.log('上传成功');
    
  } catch (err) {
    // 如果上面任何一行出错，自动执行这里
    console.log('出错了：' + err.message);
  }
}
```

**实际执行过程：**
```
1. 开始执行 createRecord()
2. 等待网络请求完成（暂停在这里）
3. 网络请求完成，获得 r 对象
4. 继续执行下一行 uploadFile()
5. 等待网络请求完成（暂停在这里）
6. 网络请求完成，执行后面的代码
7. 或者，任何一步出错 → 立即跳到 catch 块

如果中间出错：
1. 执行 createRecord()
2. 网络请求失败！
3. 不会继续往下了，直接跳到 catch 块
4. catch 块执行，弹错误提示
```

**try/catch** = "尝试执行，如果失败就进处理失败的代码块"
```javascript
try {
```

## 📚 完整语法表（快速查阅）

| 语法 | 作用 | 在代码中出现的位置 | 你会看到什么结果 |
|------|------|---------|------|
| `async handleRecordingDone() { }` | 标记这是异步函数 | 完整函数定义 | 函数内部可以用 await |
| `await createRecord()` | 暂停，等待网络请求完成 | handleRecordingDone() 创建记录时 | 等创建完成，获得 ID，才继续 |
| `await uploadFile()` | 暂停，等待上传完成 | handleRecordingDone() 上传时 | 等上传完成，获得 URL，才继续 |
| `try { ... }` | 尝试执行这些可能出错的代码 | 包裹所有网络请求的代码 | 代码正常运行 |
| `catch (err) { ... }` | 如果上面出错，执行这里 | handleRecordingDone() 最后 | 跳过后面的代码，直接弹错误提示 |
| `finally { ... }` | 无论成功还是失败，都执行 | runAI() 最后 | 一定会关闭"AI 处理中..."的状态 |
| `this.record` | 当前页面的 record 变量 | 整个函数 | 可以读或改这个变量 |
| `this.saveDraft()` | 当前页面的 saveDraft 方法 | setInterval 中定时调用 | 定时自动调用这个方法 |
| `@click="toggleRecording"` | 用户点击触发 | HTML 的按钮 | 点击按钮 → 自动执行 toggleRecording() |
| `v-if="record.id"` | 只在条件为真时显示 | HTML 中 | 有 ID → 显示，没有 ID → 隐藏 |
| `setInterval(函数, 3000)` | 每 3000 毫秒执行一次函数 | onLoad() 中启动 | 函数会自动反复执行 |
| `clearInterval(timer)` | 停止正在执行的定时器 | onUnload() 中清除 | 定时器停止，函数不再自动执行 |
| `setTimeout(函数, 1000)` | 延迟 1000 毫秒后执行一次 | submitRecord() 最后 | 1 秒后执行一次函数，只执行一次 |
| `if (条件) { } else { }` | 根据条件选择 | toggleRecording() 中 | 满足条件执行 if 块，不满足执行 else 块 |

## 💡 四个常见问题

### Q1：为什么必须用 async？不用行不行？

A：因为 `await` 只能在 `async` 函数里用。`await` 会暂停函数，普通函数不支持暂停

```javascript
// 错：没有 async，写 await 会报错
function handleRecordingDone() {
  const r = await createRecord();  // ❌ 报错！
}

// 对：有 async，就能用 await
async function handleRecordingDone() {
  const r = await createRecord();  // ✓ 正确
}
```

---

### Q2：await 前面为什么总是网络请求函数（uploadFile、createRecord）？

A：因为这些函数需要时间等待。`await` 的目的就是"等待网络请求完成"

```javascript
// 不用 await（错）
const result = uploadFile();      // 开始上传
console.log(result);               // 立即打印，此时还没上传完 ❌

// 用 await（对）
const result = await uploadFile(); // 开始上传 + 等待完成
console.log(result);               // 现在一定上传完了，有值 ✓
```

---

### Q3：setInterval 和 setTimeout 什么区别？

A：看名字：
- `setInterval` = "设置 重复执行"，会持续重复
- `setTimeout` = "设置 延迟执行"，只执行一次

```javascript
// 重复执行：3秒、6秒、9秒、12秒...都会执行
setInterval(() => {
  saveDraft();
}, 3000);

// 只执行一次：仅在 1 秒后执行一次
setTimeout(() => {
  uni.navigateBack();
}, 1000);
```

---

### Q4：这行代码怎么读？
`this.draftTimer = setInterval(this.saveDraft, 3000);`

A：从右往左读：
1. `setInterval(...)` = 创建一个定时器"
2. `this.saveDraft` = 定时执行"这个页面的 saveDraft 方法"
3. `3000` = "每 3000 毫秒（3 秒）执行一次"
4. `this.draftTimer = ...` = "把这个定时器保存到变量 draftTimer，以后可以通过这个变量停止定时"

**结果：** 每 3 秒自动调用 saveDraft() 一次，直到你执行 `clearInterval(this.draftTimer)` 才停止
