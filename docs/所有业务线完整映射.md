# 业务线映射表

## 业务线 ① 🎤 录音 → 转录 → 分析 → 提交

**用户操作：** 核心工作流

```
用户动作          →  页面响应                  →  后端动作
─────────────────────────────────────────────────────────
[打开页面]        →  onLoad()                  
                      ↓
[点"录音"按钮]     →  toggleRecording()       →  recorderManager.start()
[说话 10 秒]      →  timer 计时 10 秒        →  麦克风录音
[点"停止"按钮]    →  toggleRecording()       →  recorderManager.stop()
                      ↓                        ↓
                   onStop() 回调              handleRecordingDone()
                      ↓                        ├─ createRecord()
                      ↓                        ├─ uploadFile()
                      ↓                        ├─ transcribeAudio()
                      ↓                        └─ updateRecord()
[看转录文字]      →  textarea 显示           
[编辑文字]        →  editableText 改变       →  后台自动 saveDraft()
[点"AI 分析"]     →  runAI()                 →  extractFields()
                                              →  updateRecord()
[看 AI 结果]      →  AI 卡片显示
[点"提交"]        →  submitRecord()          →  updateRecord()
[看"已提交"]      →  页面切换               
[返回]           →  uni.navigateBack()
```

**涉及的 data：**
```javascript
record              // 核心驾驶
isRecording         // 状态
recordingDuration   // 计时
editableText        // 编辑框
audioFilePath       // 音频路径
aiProcessing        // AI 加载中
timer              // 计时器 ID
sessionId          // 环节 ID
recordId           // 记录 ID
```

**代码位置：**
- `onLoad()` 初始化
- `toggleRecording()` 开始/停止
- `handleRecordingDone()` 4 步流程
- `runAI()` 分析
- `submitRecord()` 提交


## 业务线 ③ 💾 自动保存草稿

**特点：** 后台无声，用户无感知

```
时间线            →  页面状态                  →  后端动作
──────────────────────────────────────────────────────
[onLoad()]       →  draftTimer 启动           
[0-3 秒]         →  用户操作、编辑             
[3 秒到达]       →  saveDraft() 自动执行      →  updateRecord()
[成功保存]       →  （无提示，无声）
[3-6 秒]         →  用户继续操作
[6 秒到达]       →  saveDraft() 再次执行      →  updateRecord()
[成功保存]       →  （无提示，无声）
...              →  ...                      →  ...
[用户离开]       →  onUnload()                
                 →  clearInterval(draftTimer)
```

**涉及的 data：**
```javascript
draftTimer      // 定时器 ID
record.id       // 需要存在才保存
editableText    // 需要不为空才保存
attachments     // 一起保存
```

**代码位置：**
- `onLoad()` 启动定时器
- `saveDraft()` 每 3 秒执行
- `onUnload()` 清除定时器

**特别说明：**
- ⚠️ `saveDraft()` 不会弹提示，防止打扰用户
- ⚠️ 如果保存失败，也不会弹提示，下次定时器会再试
- ⚠️ 需要 `record.id` 存在才会保存（新建时没有）

## 业务线 ④ ✏️ 编辑已有草稿（重新开始）

**用户操作：** 打开已有的草稿继续编辑

```
用户动作              →  页面响应              →  后端动作
──────────────────────────────────────────────────────
[从列表打开草稿]     →  uni.navigateTo({       
                         url: '/pages/record/index?
                              session_id=123&id=999
                       })
[页面打开]          →  onLoad(options)
                      →  options.id = 999
                      →  options.session_id = 123
[检查有 id]         →  loadRecord()           →  getRecord(999)
[加载数据]          →  填充所有字段：
                      record = {...}
                      editableText = "..."
                      attachments = [...]
[看到之前的数据]    →  textarea 显示之前编辑的文字
[继续编辑]          →  enableText 继续改变
                      →  saveDraft() 继续工作
```

**涉及的 data：**
```javascript
sessionId       // 从 options.session_id
recordId        // 从 options.id
record          // 从后端加载
editableText    // 从 record.edited_text 或 raw_text
attachments     // 从 JSON.parse(record.attachments)
```

**代码位置：**
- `onLoad()` 参数检查
- `loadRecord()` 加载数据

**特别说明：**
- ⚠️ 来源有优先级：`edited_text` > `raw_text`
- ⚠️ `attachments` 从数据库里是 JSON 字符串，需要 `JSON.parse()`
- ⚠️ 加载失败会弹错误提示

## 业务线 ⑤ 🧹 页面卸载清理资源

**特点：** 防止内存泄漏、幽灵录音

```
用户动作              →  页面响应              →  系统动作
──────────────────────────────────────────────────────
[点返回/离开页面]    →  onUnload()
                      ├─ if (timer) clearInterval()
                      ├─ if (draftTimer) clearInterval()
                      └─ if (isRecording) 
                         recorderManager.stop()
[定时器清除]         →  不再自动保存            
[强制停止录音]       →  防止幽灵录音
[内存释放]          →  释放 recorderManager
```

**涉及的 state：**
```javascript
timer               // 录音计时器
draftTimer          // 自动保存定时器
isRecording         // 正在录音？
recorderManager     // 录音管理器
```

**代码位置：**
- `onUnload()` 清理逻辑

**特别说明：**
- ⚠️ 必须清除 `timer` 和 `draftTimer`，否则页面关闭后仍在占用内存
- ⚠️ 必须停止 `isRecording = true` 的录音，防止用户不知情下继续录音

# 总结：业务线 = 用户行为路径

**是的！这 5 条业务线基本覆盖了所有用户行为：**

```
✅ 业务线 ① = 核心工作流（70% 的代码）
   用户录音 → 转录 → 编辑 → AI 分析 → 提交

✅ 业务线 ② = 附件补充（10% 的代码）
   拍照/录像 → 上传 → 管理

✅ 业务线 ③ = 后台保障（5% 的代码）
   自动保存，防止数据丢失

✅ 业务线 ④ = 模式切换（5% 的代码）
   编辑已有草稿

✅ 业务线 ⑤ = 清理工作（5% 的代码）
   离开页面时释放资源

总计 = 100% 的页面功能
```

# 下一步学习建议

**建议按这个顺序学：**

```
优先级 1 → 业务线 ①（核心，最复杂）
优先级 2 → 业务线 ②（补充，相对简单）
优先级 3 → 业务线 ③（理解自动保存机制）
优先级 4 → 业务线 ④（理解编辑模式）
优先级 5 → 业务线 ⑤（理解清理逻辑）
```

**为什么？**
- 业务线 ① 一个人就能占用你 80% 的理解时间
- 学完 ①，② 会很容易（模式一样）
- ③④⑤ 都是细节补充
