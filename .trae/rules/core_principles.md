# 核心原则

## 1. 先收集证据，再修改代码

- 修改代码前必须先搜索官方文档
- 查找官方库/SDK
- 分析相关源代码

## 2. 优先使用官方库

- Kiwi TCMS 使用 tcms-api 库
- 不要自己实现 XML-RPC 认证

## 3. 胶水编程

### 3.1 核心原则

- 凡是能不写的就不写，凡是能少写的就少写
- 凡是能 CV 就 CV（使用经过社区检验的代码）
- 站在巨人的肩膀上，而不是试图成为巨人
- 不修改原仓库代码（作为黑盒使用）

### 3.2 自定义代码的职责

自定义代码只承担以下职责：

- 组合
- 调用
- 封装
- 适配

### 3.3 标准流程

1. 明确需求
2. 使用 AI 拆解需求
3. 搜索现成的开源实现
4. 下载并整理仓库
5. 按架构体系进行组织
6. 编写胶水层代码

## 4. MCP 工具灵活使用

- 搜索时灵活使用各种 MCP 工具（GitHub、Exa、Zhipu 等）
- 不要只用内置 WebSearch，优先用 MCP 搜索
