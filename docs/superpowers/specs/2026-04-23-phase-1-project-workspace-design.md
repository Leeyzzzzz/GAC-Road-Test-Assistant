# Phase 1 设计文档：项目工作台与试验层级重构

## 1. 背景与问题

当前项目的数据模型已经存在 `projects -> test_sessions -> records` 三层关系，但首页、创建链路和页面文案仍停留在旧模型：

- 首页虽然展示的是项目列表，但主操作仍是“新建试验”
- 新建试验允许手填项目名，再由前端查找是否存在同名项目
- 项目在交互上只是试验的附属字段，不是正式的业务容器
- 首页说明文案泛化，无法告诉技术负责人“当前页面负责什么”
- 项目归档、项目删除、试验删除、项目编辑等管理能力缺失
- 当前 UI 主要依赖手写样式，组件复用度低，难以继续扩展

这导致几个直接问题：

- 技术负责人无法先按项目维度管理工作，而是被迫在试验层处理上下文
- 多车并行、同一项目下多条试验的现实业务关系没有被产品结构清晰表达
- 删除、归档、编辑等主数据管理动作没有闭环
- 后续若接入权限，当前页面结构和接口边界会产生较大返工

Phase 1 的目标不是补一个局部按钮，而是把首页到试验页的上层信息架构纠正为：

```text
项目（管理容器）
  └── 试验（核心执行对象）
        └── 记录（最小业务数据）
```

## 2. Phase 1 目标

### 2.1 业务目标

将首页重构为技术负责人的“项目工作台”，明确项目是试验的容器，试验只能在项目内创建。

### 2.2 交互目标

- 技术负责人进入首页时，默认只看到自己的未归档项目
- 点击项目后，进入该项目的试验列表页
- 试验列表按测试日期升序分组，时间越早越靠上
- 首页主操作改为“创建项目”
- 项目页主操作改为“新建试验”
- 删除操作采用强确认，归档优先于删除

### 2.3 技术目标

- 补齐项目与试验的管理接口
- 移除“前端按项目名匹配项目”的旧创建逻辑
- 为后续权限系统预留数据结构与接口边界
- UI 改造优先使用成熟组件，减少手写 CSS 与自造交互

## 3. 不在 Phase 1 实现的内容

以下内容在本轮明确不落地为正式能力，但必须在设计中预留：

- 真实登录 / 用户身份系统
- 真实项目成员与角色鉴权
- 记录级审计与权限拦截
- 首页的高级筛选、搜索、批量操作
- 记录页与导出页的全面 UI 统一改造

这些内容进入后续阶段，不允许在 Phase 1 中以“前端假权限”方式临时实现。

## 4. 核心设计原则

### 4.1 先进入上下文，再执行动作

首页先选项目，进入项目后再创建试验。禁止继续使用“首页直接创建试验，再靠项目字段补上下文”的模式。

### 4.2 项目是正式主实体，不是试验的附属字段

项目承担：

- 分类与隔离试验
- 归档与恢复
- 删除与生命周期管理
- 进入试验层的上下文入口

### 4.3 归档优先于删除

删除是高危不可恢复动作，UI 和流程都必须后置。对活跃数据的默认建议动作是归档，不是删除。

### 4.4 使用用户语言，不使用无效文案

页面标题、副标题、空状态、确认弹窗都必须明确回答：

- 当前页面是什么
- 当前页面可以做什么
- 用户下一步应该做什么

### 4.5 能用成熟轮子就不用手写

本次页面重构优先使用 `TDesign UniApp` 组件体系，避免继续手写卡片、按钮、弹层、表单和危险操作交互。

## 5. 目标用户与角色边界

### 5.1 当前显式角色

Phase 1 在产品语义上明确两类角色：

- 技术负责人：项目级管理者
- 执行人员：试验与记录执行者

### 5.2 当前实现约束

当前仓库没有真实用户、登录、角色、身份上下文，因此不能实现可靠的后端鉴权。

因此本轮策略是：

- 先把角色边界写入 spec
- 不在 Phase 1 中做真实权限判断
- 但数据库、接口和页面动作必须为权限系统预留位置

### 5.3 后续权限预留结论

后续权限系统应满足：

- 只有项目负责人可进行项目增删改、归档、恢复
- 执行人员可新建试验、维护记录
- 删除项目与删除试验属于高风险动作，后续应受更高权限控制

## 6. 数据模型调整

### 6.1 项目 Project

Phase 1 的项目最小字段定义为：

- `id`
- `name` 项目名称
- `code` 项目编号 / 代号
- `tech_lead` 技术负责人
- `archived_at` 归档时间，未归档为 `null`
- `created_at`
- `updated_at`

说明：

- `name` 和 `code` 用于识别项目
- `tech_lead` 当前仍为展示字段，不作为真实鉴权依据
- `archived_at` 用于归档状态管理，优先于布尔字段，便于未来审计

### 6.2 试验 TestSession

保留现有字段，并补充管理能力：

- `id`
- `project_id`
- `tester`
- `test_date`
- `vehicle_info`
- `route`
- `status`
- `created_at`
- `updated_at`

试验继续作为核心执行对象存在，不上升为首页主对象。

### 6.3 记录 Record

Phase 1 不改动核心记录字段，只要求试验删除时能级联删除记录。

### 6.4 唯一性策略

项目不能再依赖前端用 `name` 做弱匹配判断是否存在。

Phase 1 建议至少实现以下一种约束：

- `code` 唯一
- 或 `(name, code)` 联合唯一

推荐优先 `code` 唯一，因为它更适合长期作为项目识别码。

## 7. 信息架构

### 7.1 页面结构

Phase 1 页面层级定义为：

1. 首页：`我的项目`
2. 归档项目页：`归档项目`
3. 项目详情页：`项目概览 + 试验列表`
4. 试验详情 / 新建试验页
5. 记录页
6. 导出页

### 7.2 页面职责划分

#### 首页

负责：

- 展示未归档项目
- 创建项目
- 进入项目详情
- 触发编辑、归档、删除项目
- 进入归档项目页

不再负责：

- 直接创建试验
- 试验维度的跨项目混合浏览

#### 项目详情页

负责：

- 展示项目基础信息
- 展示该项目下的试验列表
- 按 `test_date` 升序分组
- 新建试验
- 编辑项目
- 归档项目
- 删除项目
- 编辑试验
- 删除试验

#### 新建试验页

负责：

- 在已知 `project_id` 前提下创建试验

不再负责：

- 通过手填项目名称匹配或创建项目

## 8. 页面设计

### 8.1 首页：我的项目

#### 页面定位

首页是技术负责人的项目工作台，不是试验总览页。

#### 页面结构

1. 顶部导航区
   - 标题：`我的项目`
   - 副标题：`按项目管理路试试验，进入项目后查看和创建试验`
   - 右侧入口：`归档项目`

2. 统计概览区
   - `进行中项目`
   - `进行中试验`
   - `本周新增项目`

3. 项目列表区
   - 每个项目展示：
     - 项目名称
     - 项目编号 / 代号
     - 技术负责人
     - 试验总数
     - 最近试验日期

4. 空状态
   - 标题：`还没有项目`
   - 说明：`先创建一个项目，再在项目内管理试验与记录`
   - 主按钮：`创建项目`

5. 主操作按钮
   - `创建项目`

#### 页面行为

- 默认只加载未归档项目
- 点击项目块进入项目详情页
- 项目操作放在更多菜单或等价次级操作区中

### 8.2 归档项目页

#### 页面定位

归档项目是一个独立页面，不与活跃项目混在首页展示。

#### 页面职责

- 查看已归档项目
- 恢复项目
- 彻底删除项目

#### 页面行为

- 默认按最近归档时间倒序展示
- 恢复项目后项目重新回到首页

### 8.3 项目详情页

#### 页面定位

项目详情页是进入某个项目后的工作面板。

#### 页面结构

1. 顶部项目概览卡
   - 项目名称
   - 项目编号 / 代号
   - 技术负责人
   - 试验总数
   - 最近更新时间

2. 项目操作菜单
   - 编辑项目
   - 归档项目
   - 删除项目

3. 试验列表区
   - 按 `test_date` 升序分组
   - 每组展示对应试验卡片

4. 试验卡片字段
   - 测试人员
   - 车辆信息
   - 测试路线
   - 状态：进行中 / 已结束
   - 可选：记录数

5. 空状态
   - 标题：`这个项目下还没有试验`
   - 说明：`先创建一条试验，后续记录、录音和导出都基于试验进行`
   - 主按钮：`新建试验`

6. 主操作按钮
   - `新建试验`

#### 排序规则

- 日期组之间：按 `test_date` 升序
- 日期组内：`active` 在前，`completed` 在后

### 8.4 创建 / 编辑项目

#### 字段

- `项目名称` 必填
- `项目编号 / 代号` 必填
- `技术负责人` 必填

#### 成功行为

- 创建成功后返回首页并刷新项目列表
- 编辑成功后刷新当前页面项目信息

### 8.5 创建 / 编辑试验

#### 关键变化

- 创建试验必须携带 `project_id`
- 不允许手填项目名
- 不允许在试验创建流程中顺带创建项目

#### 字段

- `测试人员` 必填
- `测试日期` 必填
- `车辆信息`
- `测试路线`

项目字段改为只读展示，不允许编辑。

## 9. 创建、归档、删除流程

### 9.1 创建项目

1. 用户在首页点击 `创建项目`
2. 填写项目表单
3. 调用项目创建接口
4. 返回首页，刷新项目列表

### 9.2 创建试验

1. 用户进入项目详情页
2. 点击 `新建试验`
3. 前端携带 `project_id` 进入试验创建表单
4. 调用试验创建接口
5. 创建成功后进入试验详情页

### 9.3 项目归档

1. 用户在首页或项目详情页触发 `归档项目`
2. 确认后写入 `archived_at`
3. 项目从首页消失
4. 用户可在 `归档项目` 页面查看与恢复

### 9.4 项目恢复

1. 用户进入归档项目页
2. 触发 `恢复项目`
3. 清空 `archived_at`
4. 项目重新出现在首页

### 9.5 项目删除

1. 用户触发 `删除项目`
2. 弹出强确认
3. 明确告知将级联删除项目下全部试验与记录
4. 用户完成确认后执行删除

### 9.6 试验删除

1. 用户在项目详情页触发 `删除试验`
2. 弹出强确认
3. 明确告知将删除该试验下全部记录
4. 用户完成确认后执行删除

## 10. 危险操作策略

### 10.1 基本原则

- 归档优先于删除
- 删除属于不可恢复动作
- 删除入口永远后置
- 删除提示必须明确后果范围

### 10.2 项目删除文案

- 标题：`删除项目`
- 内容：`删除后，该项目下的全部试验和记录将被永久移除，且不可恢复。`

### 10.3 试验删除文案

- 标题：`删除试验`
- 内容：`删除后，该试验下的全部记录将被永久移除，且不可恢复。`

### 10.4 确认形式

Phase 1 可采用以下任一方案：

- 二次危险按钮确认
- 或输入 `DELETE` 的文本确认

推荐根据 TDesign UniApp 的对话框能力选择最稳妥的实现方式，但必须满足“高于普通确认框”的强度。

## 11. UI 与 UX 方案

### 11.1 组件选型

UI 组件库采用 `TDesign UniApp` 作为 Phase 1 的主轮子。

优先使用的组件类别：

- 导航：`Navbar`
- 表单：`Form`、`FormItem`、`Input`
- 日期选择：`DateTimePicker`
- 列表 / 单元：`Cell`、等价列表容器
- 标签：`Tag`、`Badge`
- 操作菜单：`ActionSheet` 或等价组件
- 危险操作：`Dialog`

### 11.2 组件映射

#### 首页

- 顶部导航：`Navbar`
- 项目列表：列表单元或卡片型单元
- 项目状态与数量：`Tag` / `Badge`
- 更多操作：`ActionSheet`
- 空状态：统一空态区块

#### 项目详情页

- 概览卡：信息块 + `Tag`
- 试验列表：分组标题 + 列表单元
- 删除确认：`Dialog`

#### 项目与试验表单

- `Form`
- `Input`
- `DateTimePicker`

### 11.3 视觉方向

视觉风格采用“简洁、克制、偏效率工具”的方向，不使用营销型装饰。

建议视觉规则：

- 背景：浅灰白
- 卡片：白底
- 主色：深蓝灰或墨青
- 成功：低饱和绿
- 警告：琥珀色
- 危险：标准红

### 11.4 文案规则

- 页面标题必须表达业务上下文
- 副标题必须表达页面职责
- 空状态必须表达下一步动作
- 不再使用“路测助手”“智驾场地试验管理系统”作为首页主说明文案

## 12. 接口与后端改造方向

### 12.1 项目接口

Phase 1 需要支持：

- 获取未归档项目列表
- 获取归档项目列表
- 获取单个项目详情
- 创建项目
- 更新项目
- 归档项目
- 恢复项目
- 删除项目

### 12.2 试验接口

Phase 1 需要支持：

- 按 `project_id` 获取试验列表
- 创建试验
- 更新试验
- 删除试验

### 12.3 删除行为

删除项目时，后端必须级联删除：

- `test_sessions`
- `records`

删除试验时，后端必须级联删除：

- `records`

### 12.4 兼容性要求

旧接口若暂时保留，前端也必须全部切换到新业务规则，不允许继续走“按项目名查项目”的旧流程。

## 13. 权限预留设计

### 13.1 Phase 1 结论

权限系统在本轮仅做预留，不做真实实现。

### 13.2 必须预留的字段 / 关系

后续建议补充：

- `projects.owner_id`
- `project_members`
- `created_by`
- `updated_by`

### 13.3 后续角色模型建议

- `owner / tech_lead`
- `member / executor`

### 13.4 后续权限边界建议

- 项目：仅负责人可编辑、归档、删除
- 试验：项目成员可创建与编辑
- 记录：执行人员可维护记录

## 14. 验收标准

Phase 1 完成后，必须满足以下结果：

1. 首页只展示项目，不再直接创建试验
2. 项目支持创建、编辑、归档、恢复、删除
3. 试验只能在项目内创建
4. 项目详情页展示该项目下全部试验，并按日期升序分组
5. 试验支持编辑与删除
6. 删除项目会级联删除其下试验与记录
7. 删除试验会级联删除其下记录
8. 危险操作具备强确认
9. 首页、项目详情页、项目/试验表单完成 `TDesign UniApp` 化重构
10. 前端不再通过项目名查找项目后决定是否新建

## 15. 风险与注意事项

### 15.1 当前无权限系统

如果后续在未接入账号体系前强做权限，会形成前端假权限，不能作为正式方案。

### 15.2 删除动作与文件清理

本轮至少要保证数据库链路上的级联删除正确。上传文件是否同步做物理删除，可作为实现时进一步确认的技术细节，但不能影响业务删除闭环。

### 15.3 文档时机

`docs/business-flow-map.md` 不在本轮先改。应在 Phase 1 实际完成后，按真实实现结果重新整理，保证后续业务改动都基于准确链路。

## 16. 实施顺序建议

建议按以下顺序推进：

1. 数据模型与后端接口
2. 前端 API 重构
3. 首页项目工作台重构
4. 项目详情页重构
5. 项目与试验表单重构
6. 删除 / 归档交互补齐
7. 测试与文档收尾
