# 路测助手 MVP 设计文档（PRD）

## 1. 项目概述

### 目标
让路测工程师（副驾）能够快速记录并提交现场反馈。MVP 优先，给领导和同事测试效果。

### 背景
- 主机厂自动驾驶/ADAS路测场景
- 一项目可多车并行，每车2人（安全员 + 副驾记录员）
- 使用者可能是内部工程师，也可能是外包/劳务同事（不懂技术术语）

### 核心原则
- 自动化采集优先，减少手动输入
- AI 智能化处理，降低使用门槛
- 草稿不丢失，数据安全可靠
- 大模型接口可插拔，后续切换内部模型

## 2. 数据模型

```
项目 (Project)
├── id, 项目名称, 技术负责人

试验 (TestSession)
├── id, 项目id
├── 测试人员, 测试日期
├── 车辆信息, 测试路线
├── 状态: 进行中 / 已结束

记录 (Record)
├── id, 试验id
├── 原始音频文件url
├── 原始文字（语音转文字结果）
├── 附件: [{type: photo/video, url}]
├── AI提取字段:
│   ├── 问题描述（摘要）
│   ├── 问题类型（感知异常/规划异常/控制异常/接管/系统故障/其他）
│   ├── 严重程度（致命/严重/一般/轻微）
│   ├── 发生位置（GPS坐标 + 地址）
│   ├── 发生时间
│   ├── 天气状况
│   └── 车速/行驶状态（TBD，后续对接车辆数据）
├── 用户编辑后的文字内容
├── 状态: 草稿 / 已提交
├── 创建时间, 更新时间（本地时间，非UTC）
```

**三层结构**：项目 → 试验 → 记录，多车并行通过试验自然隔离。

**记录两态流转**：
- 草稿：录音/编辑中，自动保存防丢失
- 已提交：用户确认后上传到系统，技术负责人可见，支持修改

## 3. 页面结构与交互流程

MVP 共 5 个页面：

### 3.1 首页（试验列表）
- 显示当前用户参与的试验列表
- 每个卡片：项目名、路线、日期、状态
- 底部 [+ 新建试验] 按钮
- 点击进入试验详情

### 3.2 新建试验
- 填写基础信息：项目名称、测试人员、技术负责人、车辆信息、测试路线
- 日期自动填今天
- 填完自动创建试验，进入试验详情页

### 3.3 试验详情（核心页面）
- 顶部：试验基础信息摘要
- 中间：该试验下的记录列表（按时间倒序）
- 底部悬浮 [录音] 大按钮
- 点击录音按钮进入录音界面

### 3.4 录音/记录页（最核心交互）
- 大录音按钮，点击开始/停止
- 录音时自动采集：GPS位置、时间
- 录音结束后自动调用语音转文字，显示文字结果
- AI 自动提取结构化字段（问题类型、严重程度、摘要）
- 引导提示文字："请描述刚才发生了什么，包括当时的情况和感受"
- 录制中提示："正在录音...可以说：问题现象、当时车速、路况、天气等"
- 可选：添加拍照/录像附件
- 文字可编辑
- [提交] 按钮 → 状态变为已提交
- 自动存为草稿防丢失

### 3.5 导出页
- 选择试验 → 预览所有已提交记录
- 导出为 Excel/CSV（下载到本地/打开文件）
- PDF/Word 报告生成后续迭代

### 页面流程
```
首页(试验列表) → 新建试验 → 试验详情 → 录音/记录 → 提交
                                    ↑          ↓
                                    └── 记录列表 ←┘
                                              ↓
                                          导出页
```

## 4. 技术架构

```
┌─────────────────────────────────────────────┐
│                UniApp 前端 (Vue3)            │
│  企业微信小程序 ── 条件编译 ── H5            │
├─────────────────────────────────────────────┤
│  录音(RecorderManager)  拍照(chooseImage)    │
│  定位(getLocation)      本地缓存(setStorage) │
│  文件上传(uploadFile)                       │
└──────────────────┬──────────────────────────┘
                   │ HTTP/HTTPS
┌──────────────────▼──────────────────────────┐
│            后端服务 (Node.js + Express)      │
├─────────────────────────────────────────────┤
│  路由层: 试验CRUD / 记录CRUD / 导出         │
│  AI服务层: 语音转文字 / 结构化提取           │
│  文件服务: 音频/图片/视频 本地存储(→OSS)     │
│  模型适配层: 统一接口,可插拔切换大模型       │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  SQLite(MVP) → 云MySQL  +  云存储(OSS)      │
└─────────────────────────────────────────────┘
```

### 4.1 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 前端框架 | UniApp + Vue3 | 跨端，企业微信小程序+H5，后续扩展灵活 |
| 后端 | Node.js + Express | 轻量，快速出MVP |
| 数据库 | SQLite（MVP）→ 云MySQL | MVP先本地，后续可迁移 |
| 文件存储 | 本地 uploads（MVP）→ 阿里云OSS | 音频/图片/视频 |
| 语音转文字 | 智谱 GLM-ASR-2512（当前）/ 通义千问 qwen3-asr-flash（推荐切换） | 智谱有限制30秒，通义千问支持更长音频 |
| 结构化提取 | 智谱 glm-4-flash（当前）/ 通义千问 qwen-plus | 可插拔切换 |
| 导出 | xlsx库(Node) | 成熟稳定 |
| 定位 | uni.getLocation | 小程序/H5均支持，返回GPS坐标 |
| 天气 | 用GPS坐标调用天气API | 自动获取，无需手动输入（待实现） |

### 4.2 模型适配层（可插拔）

```
统一接口 (BaseAIAdapter):
  - speechToText(audioUrl) → text
  - extractFields(text) → { summary, problemType, severity, details }

已实现:
  - ZhiPuAdapter（智谱 GLM-ASR-2512 + glm-4-flash） ← 当前在用
  - QwenAdapter（通义千问 qwen3-asr-flash + qwen-plus） ← 推荐切换

待实现:
  - InternalAdapter（内部部署模型，后续对接）
```

### 4.3 草稿防丢失机制

- 编辑过程中每 3 秒自动保存到服务端（updateRecord）
- 录音文件先存本地临时路径，上传成功后清理
- 页面加载时检查未提交的草稿，提示用户继续编辑或提交（待完善）

### 4.4 条件编译处理

用 UniApp 条件编译处理平台差异：
- `#ifdef H5`：浏览器 `<a>` 标签下载文件
- `#ifndef H5`：App/小程序用 `uni.downloadFile` + `uni.openDocument`

## 5. AI Prompt 设计

### 5.1 语音转文字
直接调用 ASR API，无需自定义 prompt。当前用智谱 GLM-ASR-2512。

### 5.2 结构化提取

```
你是一个路测问题分析助手。请从以下路测记录文字中提取结构化信息。

请以JSON格式返回：
{
  "summary": "一句话问题描述",
  "problemType": "感知异常|规划异常|控制异常|接管|系统故障|其他",
  "severity": "致命|严重|一般|轻微",
  "details": "补充细节描述"
}

注意：
- problemType 只能是上述6种之一
- severity 基于描述的紧急程度判断
- 如果信息不足，尽量根据上下文推断，不确定的字段填 null
- 只返回JSON，不要其他内容
```

### 5.3 引导提示

| 阶段 | 提示文字 |
|------|---------|
| 默认 | 请描述刚才发生了什么，包括当时的情况和感受 |
| 录制中 | 正在录音...可以说：问题现象、当时车速、路况、天气等 |

### 5.4 AI报告生成（后续迭代，先定义接口）

给定一次试验的所有已提交记录，生成 PDF/Word 格式路测报告。
包含：试验概况、问题统计、按严重程度分类的问题列表、建议。

### PC 宽屏适配（H5 桌面端）

**背景**：技术负责人和领导会在 PC 浏览器查看数据，当前 UI 为纯移动端布局，宽屏下体验差。

**方案**：利用 UniApp 内置的 `topWindow` / `leftWindow` / `rightWindow` 机制，在 `pages.json` 中配置宽屏布局。手机端和小程序端完全不受影响（仅 H5 生效）。

**技术要点**：
- 通过 `matchMedia.minWidth` 控制宽屏窗口仅在屏幕宽度 >= 768px 时显示
- `leftWindow`：侧边导航栏（替代底部 Tab，显示项目/试验列表）
- `rightWindow`：详情面板（显示记录详情、导出预览、数据统计）
- `topWindow`：顶部标题栏（项目名称、用户信息）
- 录音/记录页保持纯移动端布局，不做宽屏适配（领导不需要录音）

**布局示意**：
```
手机 (< 768px)：                PC (>= 768px)：
┌──────────┐                 ┌────────────────────────────┐
│  导航栏   │                 │ topWindow (标题栏)          │
├──────────┤                 ├─────────┬──────────────────┤
│          │                 │         │                  │
│  主内容   │                 │ leftWin │   主内容          │
│  (列表)   │                 │(侧边栏) │   (列表/详情)     │
│          │                 │         │                  │
├──────────┤                 │         ├──────────────────┤
│ 底部Tab  │                 │         │ rightWindow      │
└──────────┘                 │         │ (详情/统计面板)   │
                             └─────────┴──────────────────┘
```

**优先级**：
1. 导出页 — 领导最常用，优先适配（宽屏表格展示 + 大导出按钮）
2. 首页试验列表 — 改为卡片网格
3. 试验详情/记录列表 — 左侧试验列表 + 右侧记录详情

## 8. 规则约束

| 规则 | 实现方式 |
|------|---------|
| 必须填写基础信息 | 新建试验表单必填校验 |
| 草稿不可丢失 | 每3秒自动保存到服务端 |
| 提交前用户自行确认 | 录音/记录页用户查看后手动点提交 |
| 支持修改已提交记录 | 已提交记录可编辑重新提交 |
| 大模型接口可插拔 | 适配器模式，通过环境变量切换 |
