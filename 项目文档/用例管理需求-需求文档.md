
# 路测助手 - 需求文档

| 项目 | 内容 |
|-----|------|
| 项目名称 | 路测助手 - 测试用例管理系统 |
| 创建日期 | 2026-03-14 |

---

## 一、项目背景与现状

### 1.1 团队背景
国内某主机厂智驾路测科室，负责自动驾驶（L2/L3级）的场地实验与准入测试。

### 1.2 核心痛点
目前使用"企业微信表格"管理用例，随着 L2/L3 企业及国标准入需求的增加，在线文档已无法支撑复杂的分类管理、属性关联及版本追踪。

### 1.3 合规性需求
场地实验需严格对照准入用例执行，并生成标准测试报告，作为法律准入与功能放行的核心依据。

---

## 二、建设目标与思路

### 2.1 建设原则
坚持"核心先行，逐步迭代"。首期聚焦最核心的功能闭环，后续根据实际业务反馈持续扩展。

### 2.2 主要目的
建立统一的用例管理平台，实现测试资源的资产化管理，确保场地实验过程的规范化与报告的自动化生成。

---

## 三、系统业务逻辑架构

### 3.1 层级结构

| 层级 | 定义 | 示例 |
|-----|------|------|
| **项目层 (Project)** | 最高层级，对应具体的准入目标或大型研发阶段 | L3 级自动驾驶准入项目、L2 企业标准准入测试 |
| **工作表层 (Worksheet)** | 项目下的具体测试大项或功能领域 | ODC（设计运行条件）边界识别、特殊天气场景测试、紧急避撞功能 |
| **一级分类 (Category L1)** | 工作表内的细分功能模块 | 在"ODC 边界识别"工作表下，分为：电子围栏识别、车道线识别、路沿检测等 |
| **二级分类 / 具体用例 (Category L2 / Test Case)** | 最末端的最小执行单元 | 具体的测试步骤、预期结果以及预设的标准化属性字段 |

---

## 四、测试用例管理系统

### 4.1 系统概述
开发一个Web端的测试用例管理系统，提供可维护的用例管理功能。界面要求可视化、简洁美观。

### 4.2 核心功能

| 功能模块 | 功能描述 |
|---------|---------|
| 上传功能 | 支持测试用例文件上传 |
| 在线编辑 | 提供Web界面在线编辑测试用例 |
| 删除功能 | 支持单个和批量删除测试用例 |
| 批量导入导出 | 支持Excel/CSV等格式的批量导入导出 |
| 分类筛选 | 支持按类别、标签等多维度筛选测试用例 |
| 审批权限 | 设置多级审批权限机制 |
| 企业微信集成 | 支持企业微信登录、消息通知、工作台入口 |
| 测试报告生成 | 自动生成标准测试报告 |

---

## 五、试验大纲与报告管理系统（二期）

### 5.1 系统概述
实现试验大纲和试验报告的在线管理，支持Web端和小程序访问。

### 5.2 核心功能

| 功能模块 | 功能描述 |
|---------|---------|
| 多端支持 | Web端在线文档 + 小程序 |
| 内容冻结 | 冻结不需要编辑的部分（问题、表格、格式、编号等） |
| 权限编辑 | 开放实验结果、判定和结论等需要更新区域的编辑权限 |
| 模板管理 | 支持模板更新和版本管理 |
| 在线编辑 | 在模板界面直接编辑内容 |
| 下载导出 | 编辑完成后直接下载文档 |

---

## 六、非功能性需求

### 6.1 界面需求
- 可视化界面
- 简洁美观
- 符合中国人使用习惯

### 6.2 技术约束
- 团队技术栈：Python（优先）
- 开发工具：Windows + Claude Code CLI + Trae + 大模型（GLM-5 + 豆包2.0 Code）
- 前端能力：有 React 经验，可快速学习
