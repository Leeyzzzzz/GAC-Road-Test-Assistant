# Phase 1 实施计划：项目工作台与试验层级重构

基于设计文档：
`docs/superpowers/specs/2026-04-23-phase-1-project-workspace-design.md`

## 1. 实施目标

在不引入真实权限系统的前提下，完成以下 Phase 1 结果：

- 首页只展示项目，不再直接创建试验
- 项目支持创建、编辑、归档、恢复、删除
- 试验只能在项目内创建
- 项目详情页按日期升序展示试验
- 试验支持编辑与删除
- 删除项目和删除试验具备强确认与级联删除
- 首页、项目详情页、项目/试验表单优先迁移到 `TDesign UniApp`
- 旧的“手填项目名 + 前端查找项目”链路被移除

## 2. 实施策略

### 2.1 总体顺序

本次改造按“数据与接口先稳定，页面再切换”的顺序推进：

1. 数据模型与数据库迁移
2. 后端查询与路由扩展
3. 前端 API 层重构
4. 页面重构与 UI 组件接入
5. 删除 / 归档交互补齐
6. 测试与文档收尾

### 2.2 风险控制

- 不先改 `docs/business-flow-map.md`
- 不一次性改记录页与导出页
- 不在没有用户系统的情况下硬做权限
- 删除链路先保证数据库级正确性，再考虑上传文件物理清理

## 3. 任务拆分

### Task 1：确认前端 UI 依赖接入方案

目标：
明确 `TDesign UniApp` 在当前项目中的接入方式，并确认是否需要 `uni-ui` 作为补充。

工作项：

- 检查当前 UniApp 工程是否已具备组件库接入条件
- 选定 `TDesign UniApp` 的安装与注册方式
- 确认页面级需要的组件：
  - `Navbar`
  - `Form`
  - `FormItem`
  - `Input`
  - `Button`
  - `Cell`
  - `DateTimePicker`
  - `Dialog`
  - `ActionSheet`
  - `Tag`
  - `Badge`
- 如某个交互在 `TDesign UniApp` 不顺手，确认是否由 `uni-ui` 局部补位

完成标准：

- UI 组件方案明确
- 不再继续为首页与项目页手写新的基础组件样式

### Task 2：数据库 Schema 迁移

目标：
把 `projects` 从轻量附属表升级为正式主实体。

工作项：

- 为 `projects` 表新增字段：
  - `code`
  - `archived_at`
- 设计数据库迁移策略，兼容已有数据
- 为项目唯一性加约束
  - 推荐：`code` 唯一
- 检查外键与删除策略
- 如 SQLite 外键级联不足以覆盖当前查询函数，补事务删除逻辑

完成标准：

- 历史数据可兼容
- 新字段可读写
- 唯一性规则生效

### Task 3：后端查询层重构

目标：
让查询层具备项目工作台所需的基础 CRUD 与归档能力。

工作项：

- 重构项目查询函数：
  - 获取未归档项目
  - 获取归档项目
  - 获取项目详情
  - 创建项目
  - 更新项目
  - 归档项目
  - 恢复项目
  - 删除项目
- 删除项目时级联删除：
  - `test_sessions`
  - `records`
- 重构试验查询函数：
  - 获取项目下试验
  - 更新试验
  - 删除试验
- 删除试验时级联删除：
  - `records`
- 为首页和项目详情页补聚合数据支持
  - 试验总数
  - 最近试验日期

完成标准：

- 查询层具备完整项目生命周期支持
- 试验删除与项目删除有闭环

### Task 4：后端路由与接口扩展

目标：
将查询层能力暴露为稳定接口，供前端切换。

工作项：

- 项目路由新增 / 调整：
  - `GET /api/projects` 默认返回未归档项目
  - `GET /api/projects/archived`
  - `GET /api/projects/:id`
  - `POST /api/projects`
  - `PUT /api/projects/:id`
  - `PUT /api/projects/:id/archive`
  - `PUT /api/projects/:id/restore`
  - `DELETE /api/projects/:id`
- 试验路由新增 / 调整：
  - `GET /api/sessions?project_id=...`
  - `POST /api/sessions`
  - `PUT /api/sessions/:id`
  - `DELETE /api/sessions/:id`
- 补输入校验与错误提示

完成标准：

- 接口语义与 spec 一致
- 前端不再依赖旧的项目匹配逻辑

### Task 5：前端 API 层重构

目标：
把首页、项目详情、试验创建页改到新的接口模型上。

工作项：

- 在 `client/services/api.js` 中新增：
  - 获取归档项目
  - 创建项目
  - 更新项目
  - 归档项目
  - 恢复项目
  - 删除项目
  - 删除试验
- 移除或停止使用旧流程相关封装：
  - `getProjects()` 后前端按项目名查找
- 统一错误处理

完成标准：

- 前端有完整项目 CRUD 与归档能力封装
- 新建试验只接受 `project_id`

### Task 6：首页重构为项目工作台

目标：
把首页从“试验入口页”改成“项目工作台”。

工作项：

- 重写首页文案与结构
- 主 CTA 改为 `创建项目`
- 增加 `归档项目` 入口
- 展示项目列表与轻量统计
- 项目卡片展示：
  - 项目名称
  - 项目编号 / 代号
  - 技术负责人
  - 试验总数
  - 最近试验日期
- 项目操作菜单：
  - 编辑
  - 归档
  - 删除
- 空状态重写
- 优先使用 `TDesign UniApp` 组件

完成标准：

- 首页不再出现“新建试验”
- 首页不再使用无业务意义的头部说明

### Task 7：新增归档项目页

目标：
把归档项目从首页剥离出来，形成独立入口。

工作项：

- 新增页面或路由
- 加载归档项目列表
- 支持恢复项目
- 支持彻底删除项目
- 复用首页项目列表的视觉与交互模式

完成标准：

- 首页默认只展示活跃项目
- 归档项目可查看、恢复、删除

### Task 8：项目详情页重构

目标：
让项目详情页成为“项目概览 + 试验列表”的正式工作面板。

工作项：

- 顶部展示项目概览：
  - 项目名称
  - 项目编号 / 代号
  - 技术负责人
  - 试验总数
  - 最近更新时间
- 增加项目操作菜单：
  - 编辑项目
  - 归档项目
  - 删除项目
- 试验按日期升序分组
- 组内先展示 `active`，再展示 `completed`
- 每条试验支持：
  - 查看详情
  - 编辑试验
  - 删除试验
- 增加空状态与主 CTA：`新建试验`

完成标准：

- 项目页成为唯一试验创建入口
- 试验层级展示逻辑符合 spec

### Task 9：项目表单实现

目标：
支持创建与编辑项目。

工作项：

- 设计创建 / 编辑项目表单
- 字段：
  - 项目名称
  - 项目编号 / 代号
  - 技术负责人
- 加必填校验
- 优先使用 `TDesign UniApp` 表单能力
- 根据项目列表页与项目详情页两个入口复用同一逻辑

完成标准：

- 项目可创建与编辑
- 校验与错误提示可用

### Task 10：试验表单重构

目标：
让试验只在项目上下文中创建和编辑。

工作项：

- 新建试验时移除：
  - 项目名称输入框
  - 技术负责人输入框
- 保留字段：
  - 测试人员
  - 测试日期
  - 车辆信息
  - 测试路线
- 项目仅作为只读上下文展示
- 补试验编辑能力

完成标准：

- 不再通过试验创建顺带创建项目
- `session-detail` 页的职责边界清晰

### Task 11：危险操作交互补齐

目标：
把归档与删除的 UX 做完整，不留裸操作。

工作项：

- 项目归档确认
- 项目删除强确认
- 试验删除强确认
- 删除提示文案按 spec 固定
- UI 使用 `Dialog`
- 若组件能力允许，评估使用输入 `DELETE` 的确认模式；否则采用明确的二次危险按钮确认

完成标准：

- 删除与归档具备一致的交互模式
- 危险操作不再是普通确认框

### Task 12：后端测试补齐

目标：
确保核心数据链路可验证。

工作项：

- 补项目接口测试：
  - 创建
  - 更新
  - 默认列表不含归档项目
  - 归档
  - 恢复
  - 删除
- 补试验接口测试：
  - 删除试验
- 补级联删除测试：
  - 删除项目时连带删除试验和记录
  - 删除试验时连带删除记录

完成标准：

- 关键后端链路有自动化测试覆盖

### Task 13：前端验证与收尾

目标：
确保主要流程可用，避免结构改对了但页面串不起来。

工作项：

- 手工验证以下流程：
  - 创建项目
  - 编辑项目
  - 进入项目
  - 创建试验
  - 编辑试验
  - 删除试验
  - 归档项目
  - 恢复项目
  - 删除项目
- 修正 `pages.json`、导航标题、Tab 文案
- 更新 README 中关于页面结构的描述

完成标准：

- 页面路径与标题一致
- 首页和项目页的业务文案一致

## 4. 依赖关系

关键依赖顺序如下：

- Task 2 依赖于 Task 1 的组件方案确认之外可并行思考，但数据库迁移应优先落地
- Task 3 依赖 Task 2
- Task 4 依赖 Task 3
- Task 5 依赖 Task 4
- Task 6、7、8、9、10 依赖 Task 5
- Task 11 可在 Task 6、8、10 接近完成时接入
- Task 12 依赖 Task 3、4
- Task 13 依赖全部前置任务

## 5. 风险清单

### 风险 1：历史数据兼容

已有项目数据没有 `code` 与 `archived_at`，迁移时需要考虑默认值与回填策略。

### 风险 2：删除链路与附件文件

本轮至少保证数据库级链路正确。若同时做上传文件物理删除，需要谨慎处理无引用文件和历史脏数据。

### 风险 3：组件库接入成本

`TDesign UniApp` 接入本身有一定改造成本，尤其是现有页面是 Options API 风格。页面重构时要先验证组件在当前工程中的兼容性。

### 风险 4：权限预留被误实现

本轮不应引入假权限判断或仅前端隐藏按钮的伪方案。

## 6. 完成定义

满足以下条件后，可认定 Phase 1 交付完成：

- 首页只管理项目
- 项目支持完整生命周期管理
- 试验只能在项目内创建
- 项目详情页成为试验管理入口
- 删除与归档交互完整
- 后端关键链路测试通过
- README 已更新
- `business-flow-map.md` 暂不修改，待真实实现稳定后重写
